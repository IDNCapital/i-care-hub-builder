# Refus accessibles du formulaire Professionnels I-CA.RE, REV2

Le formulaire FR/EN relie chaque refus au champ et lui donne le focus apres affichage du message. Les contraintes natives, les regles applicatives et leurs toasts restent conserves. Une correction retire le message sans deplacer le focus. Le refus URL facultative utilise `professionals.formErrorWebsite` dans les traductions FR/EN.

La livraison autonome cible `origin/main` du bundle local, `939c0eca669cb092b33ec9e5700c2240b9a54ccc`. Le test est sous `tests/advisor/Professionnels.refusAccessibles.test.tsx`, hors du perimetre `src` de `tsconfig.app.json`. Aucune dependance ni configuration de production n'est ajoutee. Le bloc de transport a partir de `setIsSubmitting(true)` et le catalogue restent conserves.

Avec les caches locaux existants de l'application sous `node_modules` et du banc sous `.ci/professionnels-refus-1011/node_modules`, lancer `python3 .ci/professionnels-refus-1011/run.py green-main`. Les 18 cas jsdom couvrent les controles Radix, les refus et corrections FR/EN, l'ordre des erreurs natives et le texte fourni par la ressource i18n active. `red-main` selectionne trois cas qui echouent sur main sans le correctif ; `red-i18n` selectionne deux cas qui echouent sur la remise precedente avec texte URL en dur. Les phases n'ecrasent pas leurs preuves existantes.

`types-qa` controle le banc. `types-project-app` et `types-project-node` lancent les configurations reelles du projet avec le compilateur de l'application. Dans le cache disponible, ces deux commandes rencontrent TS2688 sur la bibliotheque implicite `mapbox__point-geometry`, egalement sur main sans correctif. `types-explicit-app` et `types-explicit-node` utilisent les memes configurations sans alias ni exclusion supplementaire, avec seulement les types globaux explicites (`vite/client,node,react,react-dom` pour app, `node` pour node). Ces controles passent. Ils ne transforment pas la commande standard en validation verte.

Le banc ferme les capacites reseau et les producteurs avant montage, remplace la lecture du catalogue par une fixture, utilise un repertoire d'environnement vide et n'execute aucun envoi. Les preuves concernent jsdom, pas un lecteur d'ecran ni un navigateur de production. Claude reste responsable de la revue et de l'integration ; cette livraison ne constitue ni publication ni validation d'usage reel.
